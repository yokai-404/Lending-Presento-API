# Lending Presento API

REST API для формы обратной связи лендинга разработчика с AI-интеграцией.

Проект выполнен в рамках тестового задания на позицию **Junior Backend Developer**.

---

## Основные возможности

- REST API для отправки формы обратной связи
- Валидация входящих данных
- Отправка email владельцу сайта
- Отправка копии письма пользователю
- AI-анализ сообщения
- Классификация обращения
- Анализ тональности сообщения
- Автоматическая генерация ответа пользователю
- Graceful Fallback при недоступности AI
- Rate Limiting
- Логирование запросов
- Глобальная обработка ошибок
- Swagger/OpenAPI документация
- Мониторинг состояния API

- Unit и Feature тесты

## Используемые паттерны

### Controller

Контроллер принимает HTTP-запрос и передает выполнение бизнес-логике без хранения сложной логики внутри себя.

---

### DTO (Data Transfer Object)

Используется для передачи валидированных данных между слоями приложения.

Преимущества:

- строгая типизация;
- единая точка передачи данных;
- удобство тестирования.

---

### Service Layer

Вся бизнес-логика проекта вынесена в сервисы.

Например:

- обработка обращения;
- вызов AI;
- отправка писем;
- получение статистики.

Это позволяет избежать "толстых контроллеров" и делает код более поддерживаемым.

---

### Repository Pattern

Работа с моделью Contact инкапсулирована в репозитории.

Контроллеры и сервисы не зависят напрямую от Eloquent-модели, что упрощает замену источника данных и тестирование.

---

### Dependency Injection

Все зависимости подключаются через контейнер Laravel.

Интерфейсы связываются с конкретными реализациями в `AppServiceProvider`.

Например:

- AIServiceInterface → FakeAIService / OpenAIService
- ContactRepositoryInterface → ContactRepository

Такой подход уменьшает связанность компонентов и облегчает замену реализаций.

---

## Почему выбран Laravel

Laravel предоставляет готовые инструменты для построения современных REST API:

- встроенная система валидации;
- Dependency Injection;
- Middleware;
- Eloquent ORM;
- Mail;
- Queue;
- Exception Handler;
- удобное тестирование;
- хорошая экосистема.

Это позволило сосредоточиться на архитектуре приложения и реализации бизнес-логики.

## Тело запроса

```json
{
    "name": "Иван Иванов",
    "email": "ivan@example.com",
    "phone": "+79991234567",
    "message": "Здравствуйте! Хотел бы заказать разработку сайта."
}
```

---

## Правила валидации

| Поле | Правила |
|------|----------|
| name | обязательное, строка, от 2 до 100 символов |
| email | обязательное, корректный email, максимум 255 символов |
| phone | обязательное, телефон в международном формате, 10–15 цифр |
| message | обязательное, от 10 до 2000 символов |

---

## Успешный ответ

HTTP Status:

```
201 Created
```

Ответ:

```json
{
    "success": true,
    "message": "Ваше обращение успешно отправлено.",
    "data": {
        "uuid": "019f9211-cec0-73f3-b1ff-d3d47f57a13e",
        "created_at": "2026-07-24T03:01:08.000000Z"
    }
}
```

---

## Ошибка валидации

HTTP Status:

```
422 Unprocessable Entity
```

Ответ:

```json
{
    "message": "Введите корректный email.",
    "errors": {
        "email": [
            "Введите корректный email."
        ]
    }
}
```

---

## Возможные HTTP-статусы

| Код | Описание |
|------|----------|
| 201 | Обращение успешно создано |
| 422 | Ошибка валидации |
| 429 | Превышен лимит запросов |
| 500 | Внутренняя ошибка сервера |

- negative

Полученные данные сохраняются в базе данных и используются при построении статистики.

---

## Graceful Fallback

Для повышения отказоустойчивости реализован механизм Graceful Fallback.

Если OpenAI API недоступен:

- приложение не завершает обработку запроса ошибкой;
- обращение сохраняется в базе данных;
- письма продолжают отправляться;
- пользователю возвращается успешный ответ API.

В этом случае используется локальная реализация `FakeAIService`, которая выполняет простую классификацию сообщений по ключевым словам.

Таким образом приложение сохраняет работоспособность даже при отсутствии доступа к внешнему AI-сервису.

---

## Используемый Prompt

Для OpenAI используется системный Prompt, который требует вернуть строго JSON без дополнительного текста.

AI определяет:

- настроение сообщения;
- категорию обращения;
- короткий профессиональный ответ пользователю.

Это позволяет автоматически преобразовать ответ модели в массив PHP без дополнительной обработки.

# Использование AI

В проекте реализована интеграция с OpenAI API через официальный пакет `openai-php/laravel`.

AI используется как часть backend-бизнес-логики после успешной валидации обращения.

Во время обработки сообщения выполняются следующие действия:

- анализ тональности сообщения (Sentiment Analysis);
- определение категории обращения;
- генерация краткого ответа пользователю.

Результат анализа сохраняется в базе данных вместе с обращением.

Пример результата:

```json
{
    "sentiment": "positive",
    "category": "sales",
    "ai_reply": "Спасибо за обращение! Мы подготовим предложение и свяжемся с Вами."
}
```

---

## Используемая модель

```
gpt-4.1-mini
```

Модель выбрана как оптимальный вариант по стоимости, скорости работы и качеству анализа текста.

---

## Prompt

Для получения стабильного результата используется системный Prompt.

Основные требования к модели:

- определить настроение сообщения;
- определить категорию обращения;
- сформировать краткий профессиональный ответ;
- вернуть исключительно JSON;
- не использовать Markdown;
- не добавлять пояснений.

Ожидаемый формат ответа:

```json
{
    "sentiment":"positive|neutral|negative",
    "category":"sales|support|partnership|other",
    "reply":"..."
}
```

---

## Graceful Fallback

AI не является критически важной частью сервиса.

Если OpenAI недоступен:

- ошибка логируется;
- пользователю всё равно возвращается успешный ответ;
- обращение сохраняется в базе данных;
- используются значения по умолчанию.

Fallback:

```json
{
    "sentiment":"neutral",
    "category":"other",
    "ai_reply":"Спасибо за обращение! Мы свяжемся с Вами в ближайшее время."
}
```

Таким образом отказ внешнего AI-сервиса не влияет на работоспособность API.

В проекте использовался OpenAI API.

Для демонстрации работы приложения предусмотрены два режима:

- **FakeAIService** — используется по умолчанию и позволяет запускать проект без дополнительных расходов на AI API.
- **OpenAIService** — полноценная интеграция с моделью GPT-4.1 Mini через официальный пакет `openai-php/laravel`.

Переключение между режимами осуществляется через переменную окружения:

```env
AI_DRIVER=fake
```

или

```env
AI_DRIVER=openai
```

## Используемый промпт

Для анализа сообщений применяется системный промпт, который заставляет модель вернуть исключительно JSON следующего формата:

```json
{
  "sentiment": "positive|neutral|negative",
  "category": "sales|support|partnership|other",
  "reply": "..."
}
```

AI выполняет сразу несколько задач:

- анализирует эмоциональную окраску сообщения;
- классифицирует тип обращения;
- генерирует краткий профессиональный ответ пользователю.

В случае ошибки OpenAI или недоступности сервиса автоматически используется механизм Graceful Fallback, благодаря которому обработка обращения продолжается без прерывания работы API.

# Хранение данных и инфраструктура

## База данных

Для хранения обращений пользователей используется **MySQL**.

Каждое обращение сохраняется в базе данных и содержит следующую информацию:

| Поле | Описание |
|------|----------|
| uuid | Уникальный идентификатор обращения |
| name | Имя пользователя |
| email | Email пользователя |
| phone | Телефон |
| message | Текст обращения |
| sentiment | Результат анализа тональности |
| category | Категория обращения |
| ai_reply | Ответ, сгенерированный AI |
| status | Статус обработки |
| created_at | Дата создания |

Использование базы данных позволило реализовать:

- хранение истории обращений;
- построение статистики;
- последующее масштабирование проекта;
- возможность интеграции с CRM.

## Логирование

Все запросы к API проходят через middleware логирования.

Логи записываются средствами Laravel в каталог:

```text
storage/logs/
```

Логирование позволяет фиксировать:

- входящие HTTP-запросы;
- используемый HTTP-метод;
- URI запроса;
- IP-адрес клиента;
- возникающие ошибки;
- исключения;
- ошибки AI-интеграции.

Такой подход значительно упрощает диагностику и сопровождение приложения.

---

## Rate Limiting

Для защиты API от спама реализено ограничение количества запросов.

Используется собственный middleware:

```text
ContactRateLimit
```

В основе механизма используется стандартный компонент Laravel:

```php
Illuminate\Support\Facades\RateLimiter
```

При превышении установленного лимита клиент получает корректный HTTP-ответ:

```http
429 Too Many Requests
```
